## Two-Tier Model System

Every agent runs on the **high** tier by default. Three are moved down to the **low** tier — the ones whose whole job is merging or rewording findings another agent already produced, where a faster, cheaper model costs nothing in quality.

| Tier | Agents | Purpose |
|------|--------|---------|
| **High** | Triage, Synthesis, Fixer, IssueExplorer, Analyzer ×2, FactChecker, Summarizer, Parser, Respond Planner | Judgment: reading code, deciding what's wrong, writing the fix |
| **Low** | Synthesizer, Deduplicator, Styler | Merging, filtering and formatting what another agent already produced |

## The credential pool

LLM access is a **priority-ordered pool** rather than a single key. Add as many credentials as you like on the `/admin` page; dispatch walks them lowest-priority-number first and uses the first one that isn't currently rate-limited.

Each credential carries its own provider, secret, high/low model pair, and optional base URL:

| Provider | Secret | Notes |
|----------|--------|-------|
| `claude_code` | OAuth token from `claude setup-token` | Runs inference against a Claude Pro / Max subscription instead of pay-per-token |
| `anthropic` | `sk-ant-...` API key | Standard Anthropic API |
| `openai` | OpenAI API key | |
| `openai_compatible` | Provider's API key | Set a base URL — LiteLLM proxy, vLLM, anything speaking the OpenAI API |

### Failover

When a credential returns a real `429`, it's marked stale until the `retry-after` it reported (or 5 hours if it didn't say), and skipped for that long. The next dispatch drops to the next credential in the pool.

If *every* credential is stale, work isn't dropped. Sentry issues stay pending and the next dispatch tick retries them; everything else is marked deferred with a retry time, shown on the PR's status comment and cancellable from the dashboard, and redispatched automatically once a credential frees up.

Mixing a subscription credential (priority 1) with an API key (priority 2) is the usual setup: run on the flat-rate subscription until its rolling window is exhausted, then spill over to metered API traffic instead of stopping.

See [ADR-010](https://github.com/jeanclode-hq/jeanclode/blob/main/docs/adr/010-llm-credential-failover-and-rate-limits.md) for the full design.

## Choosing the fixer's model

By default the issue-resolve fixer runs on the same credential and high-tier model as every other agent. Two optional credential fields let the triage agent move **only the fixer** somewhere else:

| Field | Effect |
|-------|--------|
| **Name** | How skills and issues refer to the credential, e.g. `self-hosted`. Defaults to the provider name. |
| **Heavy-tier model** | A stronger model triage can escalate the fixer to. Leave it empty and triage never escalates. |

For issue resolution, every credential that reaches a different host is loaded into the run alongside the default one. Every other workflow, Sentry fixes included, only ever gets the default. Credentials that share a host, like several Claude subscriptions or a subscription next to an Anthropic key, collapse to the first usable one: they serve the same models, and failover already moves between them.

Triage then picks, per fix:

- **Default credential, high tier** for almost everything.
- **Another credential** only when a loaded skill or the issue itself explicitly asks for it by name. Triage never switches because an issue sounds sensitive or hard.
- **Heavy tier** when the credential has a heavy model and either a skill or the issue asks for it, or the fix is clearly heavy: a large refactor, a change spread across many files or repos, a subtle concurrency or data-integrity bug.

If a skill or issue asks for a credential that isn't configured, the fixer stays on the default and the run says so. The choice and its reason show up in the run output, in the PR description, and on the dashboard: the execution view shows the fixer's model next to its date, with the reason on hover.

A skill that keeps one organization's fixes on a self-hosted model can be as short as:

```markdown
---
name: llm-routing
description: Which LLM credential the fixer must use for this organization's repositories.
---
Every code fix in these repositories must run on the `self-hosted` LLM credential.
```

Failover is unchanged. The run's default credential is still picked by priority, a credential that is rate limited is left out of the options, and a `429` hit by a fixer on another credential marks *that* credential stale, not the default one.

## CLI configuration

The CLI reads model settings from `~/.jeanclode/config.toml` (set up with `jeanclode config`), from environment variables, or from `--model` for a one-off override:

```bash
JEANCLODE_MODEL=sonnet        # high tier
JEANCLODE_SMALL_MODEL=haiku   # low tier
```

Precedence for the high tier is `--model` → env → config file → default (`sonnet`). The low tier has no CLI flag: env → config file → default (`haiku`).

`--model` accepts only the aliases `opus`, `sonnet` and `haiku`, and rejects anything else. The environment variables and config file take any string, which is how you point at a full model id or a non-Anthropic model.

## Custom endpoint

Add an `openai_compatible` credential with a base URL to route through a LiteLLM proxy or any other OpenAI-compatible provider.

It doesn't have to be the default. Give it a name and a lower priority, and only the fixes a skill or issue sends to it will run there.

::note
Non-Anthropic models may produce lower quality results. The pipeline is built around Claude's tool use and structured output, and several stages depend on schema-conforming output to route deterministically.
::

## Recommendations

**High throughput** (many Sentry errors per day): Sonnet on the high tier, Haiku on the low. Opus adds cost with diminishing returns on well-defined fix tasks.

**Maximum quality**: Opus on the high tier for complex codebases, where the Analyzers and FactChecker benefit most from deeper reasoning.

**Cost optimization**: Haiku on both tiers. Quality will be lower, but it's workable for simple, well-scoped issues.
