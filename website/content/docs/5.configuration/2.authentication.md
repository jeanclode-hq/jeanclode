## Overview

JeanClode uses OAuth for dashboard login. Users sign in with GitHub or GitLab, the same account connected to their repositories.

| Method | Setup |
|--------|-------|
| **GitHub OAuth** | Handled by the GitHub App you configure in `/admin` |
| **GitLab OAuth** | Handled by the OAuth application you configure in `/admin` |

## Repository Access

| Provider | How it works |
|----------|-------------|
| **GitHub** | Installation tokens are minted automatically from the GitHub App, no user action needed |
| **GitLab** | Each user provides a personal, group, or project access token when connecting a GitLab organization — `api`, `read_repository` and `write_repository` scopes. **Developer** role is enough on GitLab Premium/Ultimate; **Maintainer** on Free, where JeanClode also manages a webhook per project. See [GitLab](/docs/integrations/gitlab) |

## Who can trigger the bot

Mentioning `@jeanclode-bot` is an authorization boundary, not just a trigger. The respond workflow only dispatches if the person mentioning it can already change the code themselves:

| Provider | Required |
|----------|----------|
| **GitHub** | `triage`, `write`, `maintain` or `admin` on the repository |
| **GitLab** | Developer (30) or above on the project |

Both checks are fail-closed — if the lookup can't be completed, the mention is ignored.

This is a separate thing from the connecting token above: that token is Jeanclode's own access to the repo, this is the access of the person asking it to act. Both have to pass.

## Admin Page Access

The `/admin` page uses a separate auth mechanism: the `ADMIN_SECRET` environment variable. Enter it on the admin page to access setup. The admin session lasts 1 hour.

## CLI Authentication

When running the CLI without the platform, JeanClode uses `gh` or `glab` CLI sessions for repository access:

```bash
gh auth login   # GitHub
glab auth login # GitLab
```

Set `ANTHROPIC_API_KEY` (or configure it on first run with `jeanclode config`) for the LLM.
