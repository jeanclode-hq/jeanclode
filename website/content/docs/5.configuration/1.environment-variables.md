Most configuration is done through the `/admin` page and stored encrypted in the database. Only the variables below need to be set before launch.

## Required

The backend connects to Postgres and Redis via a single connection string each, there's no separate host/user/password config.

| Variable | Description |
|----------|-------------|
| `DATABASE_URL` | Postgres connection string, e.g. `postgresql://jeanclode:<password>@postgres:5432/jeanclode` |
| `REDIS_URL` | Redis connection string, e.g. `redis://redis:6379/0` |
| `FRONTEND_URL` | Used for OAuth redirects and CORS |
| `ENCRYPTION_KEY` | Key for encrypting DB-stored credentials. Generate: `python -c "import base64, os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"` |
| `ADMIN_SECRET` | Gates the `/admin` setup page (min 32 chars). Generate: `openssl rand -hex 32` |
| `OAUTH_STATE_SECRET` | Signs short-lived OAuth state cookies. Generate: `openssl rand -hex 32` |

## Optional

| Variable | Default | Description |
|----------|---------|-------------|
| `BACKEND_PORT` | `8000` | Backend listen port |
| `FRONTEND_PORT` | `3000` | Frontend listen port |
| `NUXT_PUBLIC_API_BASE` | `http://localhost:8000` | Browser-facing backend URL, baked into the frontend at runtime |
| `BACKEND_URL` | `http://backend:8000` on Docker Compose, no default on Kubernetes | This backend's own URL, reachable from sandboxed agent containers — used for container-initiated calls back to the backend (e.g. [agent memory](/docs/architecture/memory)). On Kubernetes it must be set explicitly to a service address other pods can reach; if it's missing, container-initiated calls back to the backend are silently skipped |
| `MEMORY_CURATION_ENABLED` | `true` | Run the daily [memory curator](/docs/architecture/memory#curation), which prunes, merges and rewrites each workspace's agent memory |
| `MEMORY_CURATION_CADENCE_HOURS` | `24` | Minimum hours between two curator runs on one workspace |
| `SESSION_COOKIE_DOMAIN` | unset | Domain to scope the dashboard's session cookie to. Only read by the Kubernetes config; set it when the frontend and backend sit on different subdomains of one parent domain |

## Provider Env Overrides

By default, all provider credentials are configured in the `/admin` page. Setting any of the variables below overrides the database configuration, useful for infrastructure-as-code or secrets managers.

### GitHub {#github}

| Variable | Description |
|----------|-------------|
| `GITHUB_ENABLED` | Set `false` to disable GitHub entirely |
| `GITHUB_CLIENT_ID` | GitHub App client ID |
| `GITHUB_CLIENT_SECRET` | GitHub App client secret |
| `GITHUB_APP_ID` | GitHub App ID |
| `GITHUB_APP_NAME` | GitHub App name |
| `GITHUB_APP_PRIVATE_KEY_PATH` | Path to the App's `.pem` private key |
| `GITHUB_WEBHOOK_SECRET` | Secret for verifying GitHub webhooks |
| `GITHUB_API_URL` | Override for GitHub Enterprise (default: `https://api.github.com`) |
| `GITHUB_AUTHORIZE_URL` | Override GitHub OAuth authorize URL |
| `GITHUB_TOKEN_URL` | Override GitHub OAuth token URL |

### GitLab {#gitlab}

| Variable | Description |
|----------|-------------|
| `GITLAB_ENABLED` | Set `false` to disable GitLab entirely |
| `GITLAB_CLIENT_ID` | GitLab OAuth application ID |
| `GITLAB_CLIENT_SECRET` | GitLab OAuth application secret |
| `GITLAB_INSTANCE_URL` | GitLab instance URL (default: `https://gitlab.com`) |
| `GITLAB_WEBHOOK_SECRET` | Secret for verifying GitLab webhooks |

### LLM

LLM credentials are normally a priority-ordered pool configured in `/admin`, see [Model Configuration](/docs/configuration/model-configuration). Setting either variable below pins every dispatch to that one credential instead, bypassing the pool and its failover.

| Variable | Description |
|----------|-------------|
| `ANTHROPIC_API_KEY` | Anthropic API key (`sk-ant-...`) |
| `CLAUDE_CODE_OAUTH_TOKEN` | Claude Code OAuth token from `claude setup-token` (alternative to the API key) |

### Sentry

| Variable | Default | Description |
|----------|---------|-------------|
| `SENTRY_API_URL` | `https://sentry.io` | Override for self-hosted Sentry |
| `SENTRY_AUTH_TOKEN` | — | Instance-level Sentry auth token |
| `SENTRY_CLIENT_SECRET` | — | Sentry App signing secret override |

## PostgreSQL (Docker Compose)

Only used to bootstrap the bundled `postgres` container when running the `all`/`test` compose profiles, not read by the backend itself. Must match the credentials embedded in `DATABASE_URL`.

| Variable | Default | Description |
|----------|---------|-------------|
| `POSTGRES_DB` | `jeanclode` | Database name |
| `POSTGRES_USER` | `jeanclode` | Database username |
| `POSTGRES_PASSWORD` | — | Database password |
