## Notify when ready

A PR JeanClode opens goes through a review loop before it's worth anyone's time: review posts findings, the bot works through them, a push sends it back through review, and it repeats until a pass comes back clean. Only then is the PR in final shape.

The **Notify when ready** setting picks who gets @-mentioned in a comment at that moment.

## Setting it

**Integrations → your GitHub or GitLab organization → Notifications → Notify when ready.**

Pick any number of members of that organization. The picker lists people JeanClode has synced from the provider, so anyone with access to the org can be selected. Leave it empty and nothing is ever posted.

On GitLab, a list set on a group applies to its subgroups too, unless a subgroup sets its own.

## What actually gets posted

One comment on the PR/MR, mentioning everyone on the list, saying it's ready for them.

- **It only fires on PRs JeanClode opened.** Nothing is posted on a PR you opened yourself, even when the bot has been working on it.
- **It fires once.** Both exits of the review loop can reach it — a clean review, or a round where every finding turned out to be a false positive — and both check for an invisible marker first, so you never get two.
- **It's a comment, not the description.** The [PR Summary](/docs/workflows/pr-summary) workflow rewrites descriptions wholesale, so a mention placed there wouldn't survive.

## Renames and departures

The list stores provider identity ids, not handles. Someone renaming their GitHub or GitLab account keeps getting notified, and someone removed from the organization stops — the ids are resolved against the org's current members every time a container is dispatched.

If a saved entry no longer matches anyone in the org, the settings page says so rather than quietly dropping it.
