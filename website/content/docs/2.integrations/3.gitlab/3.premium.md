On paid plans, group webhooks exist — so this is short: one webhook on the group, a Developer token, connect.

::note
This assumes you've already done [Step 1: OAuth application](/docs/integrations/gitlab#step-1-oauth-application), including setting the webhook secret.
::

---

## 1. Create a group webhook

Your group → **Settings → Webhooks**.

| Setting | Value |
|---------|-------|
| URL | `https://your-api-domain.com/webhooks/gitlab` |
| Secret token | the webhook secret from Step 1 |
| SSL verification | enable if the URL is `https` |

Triggers:

| Trigger | Why |
|---------|-----|
| Merge request events | Review and summary on open |
| Issues events, Confidential issues events | Issue Resolve |
| Comments, Confidential comments | Carry `@jeanclode-bot` mentions |
| **Member events** | Keeps organization membership and roles in sync as people are added, removed or change access level |
| **Project events** | Tells JeanClode a new project was created — no system hook needed on paid |

One group webhook covers every project in the group and its subgroups.

---

## 2. Create a group access token

Your group → **Settings → Access Tokens**.

| Setting | Value |
|---------|-------|
| Role | **Developer** |
| Scopes | `api`, `read_repository`, `write_repository` |

**Developer** is enough — JeanClode only clones, pushes its own branch, opens merge requests and posts comments. You set the webhook up yourself in step 1, so the token never needs Maintainer.

See [Access token scopes](/docs/integrations/gitlab#access-token-scopes-reference) for what each scope is used for.

---

## 3. Connect

On the **Integrations** page, add the GitLab organization with that token. Leave **Create project webhooks** off — the group webhook already covers everything.
