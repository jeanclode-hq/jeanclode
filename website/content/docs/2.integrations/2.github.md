JeanClode uses a GitHub App for user login (OAuth) and repository access (installation tokens).

::note
**The easiest way:** go to `/admin`, enter your `ADMIN_SECRET`, and use the **GitHub → Create GitHub App** manifest flow. JeanClode creates the app on GitHub and imports all credentials automatically, no manual steps needed.
::

After configuring, connect repositories from the **Integrations** page in the dashboard.

::warning

We really recommend using this flow to save you the trouble of creating the github app yourself.
::
---

## Manual App Setup

If you prefer to create the GitHub App yourself:

### 1. Create the App

- **Personal**: [github.com/settings/apps](https://github.com/settings/apps)
- **Organization**: `github.com/organizations/{org}/settings/apps`

| Setting | Value |
|---------|-------|
| App name | `jeanclode` (must be unique across GitHub) |
| Homepage URL | `https://your-domain.com` |
| Callback URL | `https://your-api-domain.com/auth/callback/github` |
| Webhook URL | `https://your-api-domain.com/webhooks/github` |
| Webhook secret | `openssl rand -hex 32` |

### 2. Set Permissions

| Permission | Level | Purpose |
|------------|-------|---------|
| Administration | Read | Repository settings, required-status-checks (CI gating) |
| Checks | Read | CI results for the fixer's pushed commit (CI gating) |
| Commit statuses | Read | Legacy Status API CI results, for third-party CI (CI gating) |
| Actions | Read | Failing-step logs for CI gating |
| Contents | Read & Write | Read code, create branches, push fixes |
| Emails | Read | User email |
| Issues | Read & Write | Read issues, post comments |
| Members | Read | List org members |
| Metadata | Read | Basic repo info |
| Pull requests | Read & Write | Read PRs, post comments, open PRs |

Subscribe to these events:

| Event | Why |
|-------|-----|
| Installation, Installation repositories | Track which repos Jeanclode can see |
| Repository | Pick up repos created, renamed, transferred or deleted after install |
| Pull request | Review and summary on open; `synchronize` is also what drives the `on_commit` trigger mode |
| Issues | Issue Resolve |
| Issue comment, Pull request review, Pull request review comment | All three can carry an `@jeanclode-bot` mention |
| Organization | Membership sync — `member_added` / `member_removed` keep your org's people and roles current |

Two events people expect here and don't need:

- **Push** — a new commit on a PR arrives as `pull_request` with action `synchronize`, which is what the `on_commit` trigger listens for.
- **Member** — that one is about repository collaborators. Membership sync runs off **Organization**, above.

::note
Checks, Commit statuses, Actions, and Administration are all **read-only** and back CI-gated fix verification, the fixer agent can't finish its turn until your repo's own CI passes on the commit it pushed. See [Security Hardening](/docs/deployment/security-hardening).
::

## Who can trigger the bot

Mentioning `@jeanclode-bot` on a pull request or issue only dispatches the respond workflow if the person mentioning it has **triage, write, maintain or admin** access on that repository. `read` and non-collaborators are ignored, so a drive-by comment from outside your team can't drive code changes.

The check is fail-closed: if the collaborator lookup can't be completed, the mention is not acted on. This is what Administration and Members read access are used for, alongside CI gating.

### 3. Generate a Private Key

**Private keys → Generate a private key**, download the `.pem` file.

### 4. Enter in the Admin Page

Go to `/admin` → **GitHub → Paste credentials** and enter the Client ID, Client Secret, App ID, App Name, private key, and webhook secret.

::details{summary="Override with environment variables instead"}

Environment variables take precedence over the admin page configuration.

```bash
GITHUB_CLIENT_ID=<from app settings>
GITHUB_CLIENT_SECRET=<from app settings>
GITHUB_APP_ID=<from app settings>
GITHUB_APP_NAME=<your app name>
GITHUB_APP_PRIVATE_KEY_PATH=./certs/github-app-private-key.pem
GITHUB_WEBHOOK_SECRET=<your webhook secret>
```

For GitHub Enterprise Server:

```bash
GITHUB_API_URL=https://github.yourcompany.com/api/v3
GITHUB_AUTHORIZE_URL=https://github.yourcompany.com/login/oauth/authorize
GITHUB_TOKEN_URL=https://github.yourcompany.com/login/oauth/access_token
```
