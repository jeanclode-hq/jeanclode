When Sentry detects a new error or regression, JeanClode fetches the full context, traces the root cause, implements a fix, and opens a pull request, automatically.

::note
Sentry is configured per-workspace from the **Integrations** page in the dashboard, not from `/admin`. You'll create a Sentry App yourself, there's no marketplace listing.
::

---

## Step 1: Create a Sentry App

::warning
Create the integration **inside the Sentry organization you want to monitor**. JeanClode uses the organization slug from the incoming webhooks to route events, if the app is created under the wrong org, webhooks will not match.
::

Check https://docs.sentry.io/integrations/integration-platform/internal-integration/

In your Sentry organization, go to **Settings → Developer Settings → New Integration** and create a new internal integration.

| Setting | Value |
|---------|-------|
| Name | `JeanClode` (or any name you prefer) |
| Webhook URL | `https://your-api-domain.com/webhooks/sentry` |
| Verify Installation | Enabled |

Under **Webhooks**, enable:

- `issue`

Jeanclode acts on the `created`, `regression`, `resolved` and `unresolved` actions on that resource. `created` and `regression` are what start work; `resolved` and `unresolved` keep the dashboard's view of an issue in step with Sentry's.

Under **Permissions**, grant:

- **Issue & Event**: Read
- **Project**: Read
- **Organization**: Read

Save the integration. Sentry will show you a **Client Secret**, copy it, you'll need it in Step 2.

## Step 2: Connect to a Workspace

1. Sign in to the JeanClode dashboard
2. Go to **Integrations → Sentry**
3. Enter your **Client Secret** from the Sentry App you just created
4. Enter a Sentry auth token, generate one at **Sentry → Settings → API → Auth Tokens** with `org:read`, `project:read` and `event:read` scopes. `org:read` is what lets Jeanclode resolve the organization and its projects; without it the connection succeeds and then syncs nothing
5. Click **Connect**, JeanClode syncs your Sentry projects

## Step 3: Map Projects to Repositories

::warning
**This step is required.** Without a project mapping, JeanClode cannot locate the code to fix and will skip every incoming issue for that Sentry project. No PRs will be opened.
::

In the **Integrations** page, map each Sentry project to its repository:

```md
sentry-project: my-api  →  github: org/my-api-repo
```

Add one mapping per Sentry project. JeanClode uses this to know which codebase to fix when an error fires. If a mapping is not set, no workflow will be launched.
