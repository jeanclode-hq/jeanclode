## Overview

The PR Summary workflow reads the diff and the existing description, then **rewrites the PR/MR description** with a short bullet summary of what changed and why, so a reviewer understands the change before opening a single file.

It writes the description rather than adding a comment on purpose: a comment scrolls away under review threads, and the description is the first thing anyone reads.

## Pipeline

```
PR / MR opened, or `jeanclode:summary` attached
  │
  ▼
Summarizer
  2-6 bullets, every link carried over
  │
  ├─────────────────────────┐
  ▼                         ▼
Parser                    File Summarizer
  Tightens the wording      One line per changed file
  │                         │
  ├─────────────────────────┘
  ▼
Update the PR/MR description
```

Three agents, no codebase exploration. The diff and the existing description are enough for a summary, and no agent gets file tools, so a summary run can't touch your repo. The file summarizer starts once the summarizer has answered and reuses its prompt cache for the description and diff, so reading a large diff a second time costs a fraction of the first; it then runs alongside the parser. If it fails, the description is posted without the per-file list.

Lockfiles, minified bundles, images, snapshots and generated code show up in the diff as a path and a `+/-` line count only. Their content never reaches an agent, in this workflow or in code review.

## Links are carried over, not lost

The summary replaces the description wholesale, so every link the old description carried is reproduced verbatim in the new one, with the relationship it carried intact: "Fixes *(Sentry issue)*", "Depends on *(MR)*", "Follow-up to *(PR)*". A link with no stated relationship gets its own bullet. The only things dropped are the PR's own URL, images and badges.

This is why the mention that tells your team a bot-opened PR is ready lives in a comment rather than in the description, see [Autonomous Loop](/docs/architecture/autonomous-loop).

## Summary Format

A short bullet list. Each bullet starts with a verb, combines the *what* and the *why* in a sentence or two, and merges related changes rather than listing every file. Trivial changes (whitespace, import shuffling) are omitted unless they're the point of the PR.

Below it sits a collapsed **Changes per file** dropdown: a two-column table with one row for every file the PR touches, so it takes no room until someone opens it.

```md
<details><summary>Changes per file (3)</summary>

| File | Content |
|---|---|
| `src/api/users.py` | Adds pagination params to the list users endpoint |
| `tests/api/test_users.py` | Tests paginated user listing and the page size cap |
| `uv.lock` | Updates lockfile |

</details>
```

The file list comes from the diff itself; the model only writes each line, and a path it invents is dropped. On a re-run the previous dropdown is removed before the summarizer reads the description, so it never leaks into the bullets.

## Triggering

**Automatically**: when a PR/MR is opened, or when `jeanclode:summary` is attached. Which of those applies depends on the org's `summary` trigger setting. A fix JeanClode opens attaches the label itself as part of finishing.

**From the CLI**:

```bash
jeanclode summary https://github.com/org/repo/pull/42
jeanclode summary https://gitlab.com/group/project/-/merge_requests/7

# Dry run, print the summary without writing it:
jeanclode summary https://github.com/org/repo/pull/42 --dry-run
```
