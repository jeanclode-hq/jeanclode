## Overview

The Code Review workflow runs a 7-agent pipeline when a PR or MR is opened, or when it's tagged with the `jeanclode:review` label, most commonly by [Sentry Fix](/docs/workflows/sentry-fix) or [Issue Resolve](/docs/workflows/issue-resolve) handing off a completed fix, or by [JeanClode Respond](/docs/workflows/jeanclode-respond) after pushing one. See [Autonomous Loop](/docs/architecture/autonomous-loop) for how these workflows chain together. Agents explore your codebase for context, verify findings against actual code, and post inline comments directly on the diff.

## Pipeline

```
PR / MR opened, or `jeanclode:review` attached
  │
  ▼
IssueExplorer
  Finds linked issues in the PR description, summarizes context
  │
  ▼
2× Analyzer (parallel, with tools)
  Each explores the codebase via Read/Grep/Glob/Bash
  and identifies potential issues in the diff
  │
  ▼
Synthesizer
  Merges findings from both analyzers
  │
  ▼
Deduplicator
  Removes findings that duplicate existing discussion
  (skipped when the PR has no discussion yet)
  │
  ▼
FactChecker (fresh context)
  Re-verifies each claim against actual code
  │
  ▼
Guardrail
  Deterministic secret scan — drops any comment whose own text
  would leak a credential
  │
  ▼
Styler
  Makes comments concise and actionable
  │
  ▼
Post inline comments
  a comment the provider rejects for being outside the diff
  is recovered as a top-level comment rather than dropped
```

Any stage coming back empty short-circuits straight to posting, which then posts LGTM instead of comments.

### Why Multiple Agents?

Most AI reviewers use a single prompt ("review this diff"), which leads to hallucinations. This pipeline:

1. **Parallel exploration**, 2 independent analyzers with code search tools find issues a single pass would miss
2. **Adversarial fact-checking**, FactChecker starts with fresh context and independently re-verifies every claim
3. **High signal, low noise**, only findings that survive fact-checking get posted

## On a PR JeanClode opened itself

A PR opened by the bot runs a review loop, and this workflow is one of its two exits:

- **Findings remain** → a single `@jeanclode-bot` follow-up comment asks the bot to sweep them: verify each isn't a false positive or already fixed, resolve the thread if it is, otherwise fix it and then resolve. That dispatches [JeanClode Respond](/docs/workflows/jeanclode-respond), and if it pushes anything, `jeanclode:review` is re-attached and this workflow runs again.
- **LGTM** → the loop has converged. The people configured in the org's notify list get @-mentioned in a comment saying the MR is ready.

The follow-up sweep only fires on bot-authored PRs, which is what keeps a human's PR from being swept, and it's the only place the bot ever mentions itself.

## Two-Tier Model System

| Tier | Agents | Rationale |
|------|--------|-----------|
| **High** | IssueExplorer, Analyzer ×2, FactChecker | Deep reasoning and code exploration, use the strongest model |
| **Low** | Synthesizer, Deduplicator, Styler | Merging and formatting, use a faster, cheaper model |

See [Model Configuration](/docs/configuration/model-configuration).

## Supported Platforms

- GitHub Pull Requests, inline review comments
- GitLab Merge Requests, inline discussion notes

## Triggering

**Automatically**: when a PR/MR is opened, or when `jeanclode:review` is attached. Which of those applies depends on the org's `review` trigger setting.

**From the CLI**:

```bash
jeanclode https://github.com/org/repo/pull/42
jeanclode https://gitlab.com/group/project/-/merge_requests/7

# Dry run, analyze without posting:
jeanclode https://github.com/org/repo/pull/42 --dry-run
```

**From the dashboard**: open the **Pull Requests** page and click the review button on any PR.
