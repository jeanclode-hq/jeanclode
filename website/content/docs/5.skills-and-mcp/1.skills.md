## What a skill is

A skill is a folder with a `SKILL.md` in it: a short description up top, then the instructions for doing one thing your way — how you deploy, your framework's conventions, how to query your metrics. The same format Claude Code, `npx skills` and Codex use, so a skill written for any of them works here unchanged.

The agents load the installed skills on every run and use the ones that fit the task.

## Connecting a source

**Integrations → your GitHub or GitLab organization → Skills → Connect source.** Paste any of:

| You paste | What you get |
|---|---|
| `owner/repo` | A GitHub repo, the same shorthand as `npx skills add` |
| `https://github.com/org/repo`, `https://gitlab.example.com/group/sub/repo` | The whole repo |
| `git@gitlab.example.com:group/repo.git` | The same repo; SSH URLs are read over HTTPS |
| `https://github.com/org/repo/tree/v2/.claude/skills` | Only the skills in that folder, at that branch or tag |
| `https://gitlab.example.com/group/repo/-/blob/main/skills/deploy/SKILL.md` | Just that one skill |

What happens next depends on the repo:

- **It has `.claude-plugin/marketplace.json`** — it's a Claude Code marketplace, and you install its plugins.
- **It doesn't** — every folder with a `SKILL.md` becomes something you can install on its own. A repo whose root is a `SKILL.md` is a single skill.

Then click **Install** on the ones you want, or **Install all**.

::note
In a web link, the branch or tag is one path segment. A branch with a `/` in its name (`release/2.0`) reads as branch `release` plus folder `2.0`; link a tag, or the plain repo, instead.
::

## Staying up to date

Installed skills follow the source on every run — push a change to the repo and the next run uses it. There's nothing to update in JeanClode.

The exception is a version someone chose on purpose:

- **A marketplace entry with a `ref` or `sha`** is cloned at that tag, branch or commit. A `sha` wins over a `ref`, and keeps working even if the branch or tag is deleted later.
- **A link to a branch or tag** (`/tree/v2/...`) stays on it.

## Marketplace plugin sources

A marketplace lists each plugin with a `source`. JeanClode follows [Claude Code's schema](https://code.claude.com/docs/en/plugins/marketplace-reference#plugin-sources):

| Source | Example |
|---|---|
| Relative path | `"./plugins/review"`, or a bare `"review"` under `metadata.pluginRoot` |
| `github` | `{"source": "github", "repo": "org/plugin", "ref": "v2"}` |
| `url` | `{"source": "url", "url": "https://gitlab.example.com/team/plugin.git", "ref": "1.4.0"}` |
| `git-subdir` | `{"source": "git-subdir", "url": "org/monorepo", "path": "tools/lint"}` |

A plugin's `skills` field — on the marketplace entry, or in the plugin's own `plugin.json` — can name a skill folder or a folder of skills, relative to the plugin. That's how several plugins share one repo: each lists only its own skills.

`npm`, `archive` and `command` sources aren't supported. They show as **Unsupported source** with the reason, and can't be installed, rather than silently doing nothing.

## Private repos and security

- **Private and internal repos** are read with your organization's own GitHub App or GitLab token. That token is only ever sent to your organization's own host: a source on another host is read anonymously, so it has to be public.
- **GitLab sources** must live on your organization's GitLab, or on the GitLab instance JeanClode is connected to. Any other host is refused.
- **Nothing a source ships runs on JeanClode's servers.** The backend only reads files through the GitHub and GitLab APIs. Skills are cloned inside the run's sandbox, through its proxy, and only the folders you installed are loaded; paths or symlinks that point outside the cloned repo are refused.
- A skill's scripts can run when the agent uses the skill, inside that same sandbox. Install skills from repos you trust, the way you would a dependency.
- A skill that calls an API or logs in to a web app needs credentials: add them with **Add auth** on the installed skill. See [Credentials](/docs/skills-and-mcp/credentials).
