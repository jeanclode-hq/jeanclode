Docker Compose is the simplest way to deploy JeanClode. Ideal for small teams and single-server setups.

## 1. Clone and Configure

```bash
git clone https://github.com/jeanclode-hq/jeanclode.git
cd jeanclode
cp .env.example .env
```

## 2. Set Required Variables

Open `.env` and fill in:

```bash
# PostgreSQL password, set it in both places:
POSTGRES_PASSWORD=<strong-password>
DATABASE_URL=postgresql://jeanclode:<strong-password>@postgres:5432/jeanclode

# Encryption key for DB-stored credentials:
# python -c "import base64, os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"
ENCRYPTION_KEY=<generated>

# Gates the /admin setup page (min 32 chars):
# openssl rand -hex 32
ADMIN_SECRET=<generated>

# Signs OAuth state cookies:
# openssl rand -hex 32
OAUTH_STATE_SECRET=<generated>
```

Everything else, GitHub App credentials, GitLab OAuth, LLM API key, is configured through the admin page after launch.

## 3. Launch

```bash
docker compose --profile all up -d
```

Check the backend is up:

```bash
curl http://localhost:8000/health
docker compose logs backend -f
```

## 4. Finish Setup

Go to `http://localhost:3000/admin` and configure GitHub, GitLab, and LLM. See the [platform guide](/docs/getting-started/admin-dashboard).

## Profiles

| Profile | Services | Use case |
|---------|----------|----------|
| `all` | postgres, redis, docker-proxy, migrate, backend, frontend, cli-worker, security-proxy | Full stack (recommended) |
| `app` | docker-proxy, migrate, backend, frontend | You have external PostgreSQL and Redis |
| `worker` | cli-worker, security-proxy | Build the agent + sidecar images alongside a stack running elsewhere |
| `test` | postgres, redis, docker-proxy, migrate, pgweb | Local development / CI — dependencies only, no app |

`docker-proxy` is a scoped Docker socket proxy: the backend dispatches agent containers through it rather than being handed the host's Docker socket directly.

## Sandboxing

Every dispatched agent runs as a pair, exactly as on Kubernetes: the CLI
container holds no credentials and is pointed at a **security-proxy**
sidecar over a shared network namespace. The sidecar owns every secret
(LLM key, git tokens), enforces a per-execution host allowlist, and is the
only process with outbound internet access. The `cli-worker` and
`security-proxy` services exist only to **build** those two images locally
(`ghcr.io/jeanclode-hq/cli` and `ghcr.io/jeanclode-hq/security-proxy`) — the
backend starts one of each per execution and tears them down on exit.
`SECURITY_PROXY_IMAGE` / `WORKER_IMAGE` override the image references if you
publish your own. `pgweb` is a database browser on the `test` profile only.

```bash
# .env
```


## Custom Domain

The backend has no `/api` prefix on its routes, so the reverse proxy must strip it, and `NUXT_PUBLIC_API_BASE` must point the browser at the proxied path, not the internal service:

```bash
FRONTEND_URL=https://jeanclode.example.com
NUXT_PUBLIC_API_BASE=https://jeanclode.example.com/api
```

Use your preferred reverse proxy (Caddy, Traefik, nginx) to terminate TLS:

```
# Caddy
jeanclode.example.com {
  handle_path /api/* {
    reverse_proxy backend:8000
  }
  reverse_proxy frontend:3000
}
```

## Updating

```bash
git pull
docker compose pull
docker compose --profile all up -d
```

Migrations run automatically on startup.
